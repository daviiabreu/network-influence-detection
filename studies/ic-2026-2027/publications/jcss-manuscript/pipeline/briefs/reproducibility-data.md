# Brief: reproducibility and data statements

**Target:** `main.tex` Statements and Declarations and, where method detail is needed, `sections/methods.tex`. **Budget:** 120–200 words for the availability statement, plus up to 250 words for reproducibility methods.

**Claims:** Say what data are synthetic, whether any third-party microdata were actually used, where validated code, parameters, seeds, run manifests, generated tables/figures and environment records can be accessed, and any licence or access restrictions. Distinguish planned release locations from deposits that exist. State what can be reproduced now and what awaits frozen protocol, gate passage and final results. Include funding, competing interests, ethics and author contributions only after factual confirmation.

**Evidence:** `claim-evidence.md` V01–V17 for planned simulation and provenance, V18 and V22 for unfilled output and availability, MAP01–MAP08 if map artifacts are discussed. Consult validated run manifests and release inventory only when they exist. See official venue checklist for the declaration form; venue policy is not evidence that a deposit exists.

**Style and handoff:** Clear academic English. Every empirical claim links to a ledger ID and exact artifact. Do not claim public data/code or human approval from a draft. Return the actual location, revision/hash and access terms for each released item, or leave the existing submission blocker.
